## 1. The route: `/embed/?scene=<slug>&audience=<a>`
Pages can't rewrite `/embed`, so the route is `embed/index.html`. The site requests `/embed/?…`.

### Behaviour (must)
- **No login.** The `#kt=…` hash handoff (`index.html:37-116`) and `?sessionToken=` / `?enrolmentId=` (`vendor/app.js` ~`:11612`, `:12334`) are not read.
- **No session write.** None of these are called:
  - `fn_capture_intake`
  - `fn_my_session_state`
  - `fn_bind_conversation`
  - `session-start`, `session-end`, `session-upload`
  - the tutor-chat webhook
  - billing, quota or session tables of any kind
- **No audio and no voice connection, ever (037 ruling 2).** Narration is a pre-recorded file played by the parent page. The frame must ignore `unmute`/`mute` if it ever receives them.
- **One scene only.** It renders exactly one manifest-registered scene. An unknown slug posts nothing, so the site times out to its poster after 4 s.
- **`audience`** is informational only. It never changes what data is read.
- **The framing stopgap (§3) must be included.**

### 1.1 Messages
The shapes are identical to `src/embed/protocol.ts`. Steps are **1-based**, and `n = 0` means an empty board.

| Direction | Message | Meaning |
|---|---|---|
| parent → frame | `{cmd:'play'}` | Autoplay the steps from the current one. Stop at the last step; don't loop. |
| parent → frame | `{cmd:'pause'}` | Freeze the board, including the 2D RAF loop through `window.KARKA_PAUSED` (`vendor/science-scenes-2d.js:161`). |
| parent → frame | `{cmd:'reset'}` | Pause, then go to step 0. |
| parent → frame | `{cmd:'step', n}` | Pause autoplay and go to step `n` (clamped 0…N). The last step's drawing animates; earlier steps render complete. Idempotent. The parent sends it from scroll, **or from the narration clock while narration plays**. |
| parent → frame | `{cmd:'unmute'}`, `{cmd:'mute'}` | **Reserved; never sent (037 ruling 2).** A frame must ignore them. |
| frame → parent | `{evt:'ready', n?, scene?, steps?:[{n, say}]}` (v2) | Sent after the scene has mounted. `n` = the total step count, which must be ≤ 8. In v2, `n` may be omitted when `steps` is sent, and the total is then `steps.length`. The site uses each `say` line as that step's caption, and falls back to copy.ts for any line that is missing or `TODO:VB`. **It can arrive more than once:** a reloaded frame sends it again as a fresh board at step 0. The parent must treat every `ready` as a re-initialisation and re-send `pause`, or the current `step`/`play`. |
| frame → parent | `{evt:'step', n}` | Sent every time the board shows step `n`, including as an echo of `cmd:'step'`. |

**Origin rules (both sides):**
- The frame accepts commands only when `event.source === window.parent` and `event.origin` is in `{'https://karkalabs.ai', 'https://www.karkalabs.ai'}`, plus `'self'` for local testing.
- The frame posts only to the parent's allowlisted origin. It never uses `'*'`.
- The parent checks `event.source` and `event.origin` in the same way.

### 1.2 How steps map onto today's engine
Scenes have `controls[{label, act}]`, not numbered steps. For example, two-clocks has `run / top / reset / strobe` (`scenes/p11-scenes-ch3.js:363-366`). Board Previous/Next change the *subtopic*, and `manualNextStep` (`vendor/app.js:947`) is unbound.

The embed therefore needs a **per-scene step script**: ≤ 8 entries `{act, say, t}`.
- `act` is an existing control act, or `null` for "draw only".
- `say` is the tutor's line.
- `t` is that line's offset in the scene's narration file.
- `step n` replays entries 1…n and posts `{evt:'step', n}`.
- The site's `captions` (`{t, text}`) are the same list, so the words and the timings live in one place.

### 1.3 Narration (ruled in 037)

  - While it plays, `timeupdate` picks the caption (the last `t` ≤ `currentTime`), and the parent sends that step to the board.
  - When it is paused or ended, scroll drives the steps again.
  - It pauses when the embed leaves view.
  - Under reduced motion, the captions (a transcript list) advance with the audio, and the board stays on the poster.

## 3. Framing: `frame-ancestors 'self' https://karkalabs.ai https://www.karkalabs.ai`

**The Karka frontend cannot set this header on GitHub Pages.**
- Pages has no per-path headers.
- `frame-ancestors` in a `<meta>` CSP is ignored.
- `X-Frame-Options` is header-only.

**Ruling (037): ship the in-page check as the stopgap.** The Cloudflare header (a Pages `_headers` rule, or a Worker on `/embed/*`) is its own future word, with Vinodh deciding the timing. The nameservers are not moving yet.

### The stopgap, as implemented in the placeholder (the real route must copy it)
```js
if (window.parent !== window) {
  const ancestors = location.ancestorOrigins ? Array.from(location.ancestorOrigins) : [parentOriginFromReferrer];
  if (ancestors.length === 0 || ancestors.some((o) => !o || !ALLOWED.has(o))) {
    document.body.dataset.blocked = 'true';
    document.body.replaceChildren();   // render nothing, post nothing, accept nothing
    return;
  }
}
```

### Its limits (what the stopgap does NOT give us)
1. **It is JavaScript, not a browser-enforced policy.** It only runs if the page's scripts run.
   - A hostile page can frame the route with `sandbox` and no `allow-scripts`. The check then never runs, but nothing renders either, because the board is drawn by script, so the framer gets an empty page.
   - Any content that sits in the HTML itself *would* show. **Keep the embed shell's static HTML empty.**
2. **Firefox has no `location.ancestorOrigins`.** There the check relies on `document.referrer`.
   - A framer can suppress the referrer (`referrerpolicy="no-referrer"`). The check then fails **closed**, and the frame goes blank.
   - The flip side: if our own site ever sends no referrer, Firefox visitors get the 4 s poster fallback. The site's iframe sets `referrerPolicy="strict-origin-when-cross-origin"` deliberately, which sends the origin.
3. **It can't stop the page being fetched, cached or scraped.** It only stops it running inside a foreign frame.
4. **There is no violation reporting.** A header CSP can report to an endpoint; this can't.
5. **Nested frames:** in Chromium and Safari every ancestor must be allowlisted. In Firefox only the direct parent is seen.
6. **Residual risk stays small only while the frame has no side effects.** That means no audio, no voice, no writes, and no controls that do anything outside the board. Any future interactive or side-effecting feature makes the header (option B) a **precondition**.
